# Historical compatibility and text auditing

The compatibility suite combines the existing form-history corpus with 110 distinct JSON layouts extracted from 271 reachable historical resource documents. It covers forms, skills, racial appearance/economy and stats, techniques, entities, quests and sagas. Each fixture identifies its Git blob and original resource path. Regenerate the resource corpus with `python3 scripts/collect-content-history.py`; the collector reads Git objects without switching branches or touching player files.

Additional regression fixtures cover custom NPC definitions, the earlier `hairCode` alias, placements, dialogue choices and completion/purchase rules. Those APIs were introduced by this fork; they do not have pre-fork upstream save formats. Tests preserve unknown fields and normalize legacy prices, form aliases and reward difficulty prefixes. This evidence covers the formats present in repository history and the documented API layouts; it cannot reconstruct undocumented external addon formats.

Native GameTests cover JSON adapter round trips through current content classes, backup failures, repeated backups, invalid-default fallback, rejection of duplicate quests and purchase refusal transactions. A rejected quest is not migrated, including when the default updater had prepared a newer definition. Existing files are replaced only after their original bytes have been backed up. Missing-default creation never overwrites an existing file.

For translation, run `python3 scripts/audit-player-text.py` and `python3 -m unittest discover -s scripts/tests -v`. The source audit checks catalog keys and text entry/rendering paths; its regression tests exercise hidden appended labels, message arguments, formatted units and local variable propagation. The client language hook complements it by recording dynamic keys that exhaust the configured fallback chain. See [Config translations](Translations) for the API and [Content configuration](Content-configuration) for schemas and rollback.
