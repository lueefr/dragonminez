# DragonMineZ 2.2 - Hotfix 7

Minecraft 1.21.1 NeoForge maintenance update.

### Fixed

- Corrected the camera projection and overlay depth handling for player aura outlines and sparks, which could appear displaced from the character.
- Improved muscle overlay rendering with shader packs.
- Routed Otherworld landmark placement through vanilla's per-chunk feature pipeline. The legacy Otherworld column-cache codec is retained for compatibility while the custom column-cache implementation is removed from the shipped generation graph.

### Validation

- Build completed successfully; all 8/8 GameTests passed. The packaged JAR SHA-256 is `63a7985d22ed1ca3fdf671b9c0d00652966d5f4a734550a775bce147c6f560be`.
- Aura outlines and sparks stayed aligned with the player in screenshots captured without shaders and with Iris plus Complementary Shaders r5.9.2. The muscle texture remained visible in both checks using `bodyType=1`.
- All 348 structure-template NBT files passed exact round-trip comparison.
- With Distant Horizons 3.3.1 and DH SeedGen 0.8.0 using server generation, Otherworld chunk `(-1, 61)` was generated and its full chunk contained an ANDESITE landmark at `(-1, 162, 980)`. The SeedGen FullData is being rechecked with the dimension's vertical coordinate offset; its landmark representation remains unconfirmed.
- Distant Horizons 3.3.1 native generation was tested with `chunkGeneratorMode=INTERNAL_SERVER` and `generatorPlan=CHUNKS_ONLY`; DH SeedGen was loaded but disabled (`enabled=false`, `serverGeneration=false`). The generated full chunk contained the same ANDESITE landmark. In decoded FullData local column `(63, 20)`, raw vertical coordinates are relative to Otherworld's `minY=-64`: ANDESITE at raw Y 226–228 maps to world Y 162–164, matching the landmark at world Y 162–163. Other exposed blocks in the column also align with the template. No visual overlay was captured.

### Compatibility limits

- The inspected native Distant Horizons FullData coordinates are consistent with the landmark after normalization by `minY=-64`; this server-only check had no player and captured no visual overlay, so it does not establish visual LOD compatibility. The DH SeedGen 0.8.0 FullData is still being rechecked with this normalization, so its landmark representation remains unconfirmed. Voxy, Voxy SeedGen, other SeedGen versions, and other LOD addons were not tested.
- An LOD addon may use a generation pipeline that skips custom chunk features, including landmark placement.
- Existing cached LOD data may need rebuilding with the relevant addon's own tools. No world save or region file deletion is required by this update.

### Requirements

- Minecraft 1.21.1 and Java 21.
- NeoForge 21.1.238 or a later 21.1 release.
